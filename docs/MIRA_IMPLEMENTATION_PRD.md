## 1. 目标、非目标与口径

**交付目标**：一个可安装的 Mira 桌面客户端，离线首次启动可进入内置 Harness；Novel Studio 作为受管理的第一方子应用安装、切换和更新；两者共享必要的平台能力，但保留各自界面和数据。任务、审批、草稿、成果在切换或重启后按约定恢复。

**不在第一阶段**：Mira Vision 业务、任意第三方插件市场、可执行代码安装包、云同步、完整 Git IDE、媒体生成适配、差分更新、复杂多 Agent 编排及移动端。Vision 的同级空目录已预留，但尚无 Git 仓库或业务工程；本仓库只规划未启用的接入配置，不进入应用列表、设置、构建或发布。

本文件是**开发实施 PRD**，不是当前实现状态清单，也不是立即删除旧小说代码的命令。Novel Studio 与 Vision 的业务工程以后各自建 Git 仓库维护；本仓库最终仅保留其必要的平台接入配置。当前小说页面和存储仍在本仓库，须在独立包、旧作品读取及回退验收后迁出，用户数据不得随源码删除。模型供应商的数据结构、React 选型及应用包协议细节在实施时单独评审，不在这里虚构成既定接口。

### P0–P3 表示什么

| 关口 | 含义 | 放行条件 |
| --- | --- | --- |
| P0：界定与基线 | 确定该模块保留、退出和迁移的边界；准备设计、现状证据与可复现的核心场景 | 明确负责人、依赖、验收用例和回退入口；待定选项有明确决定时点 |
| P1：最小可用改动 | 只改能形成一条真实闭环的代码，保留现有用户数据 | 本模块的核心场景可在开发版使用，针对改动有自动化检查 |
| P2：双应用集成 | 接入真实平台、实际数据和应用切换；处理旧版本兼容 | Harness 与 Novel Studio 的相关链路联调通过，异常路径可恢复 |
| P3：发布验收 | 生产包、旧数据、失败恢复及桌面交互验收 | 满足模块验收；macOS、Windows 和真实模型的证据分别记录，不以构建代替运行验收 |

P 是**同一模块内部的完成关口**，不是需求优先级，也不要求所有模块的 P1 同时开工。每个模块必须逐关口通过，且满足跨模块依赖，才可宣称第一阶段完成。React 已确定为 Harness UI 目标，旧 Vue 页仅作迁移期的生产回退，不再作为最终交付路线。

## 2. 改动总览与依赖

第一阶段分为 **7 个大模块**，另有贯穿各模块的数据与验收要求：

| 模块 | 主要归属 | 核心产物 | 先决条件 |
| --- | --- | --- | --- |
| A. Electron 平台服务 | 桌面主程序 | 清晰的服务、IPC、模型与安全边界 | 现有服务和 IPC 清单 |
| B. Platform SDK 与长任务 | 宿主 + 两应用适配层 | 版本化能力、应用身份、任务查询与成果引用 | A 的能力所有者确定 |
| C. Vue Shell 与统一设置 | 桌面壳 | 固定导航、应用切换、新设置页、昼夜主题 | 应用清单与设置归属明确 |
| D. Mira-Harness | 默认应用 | 真任务工作台、审批、历史与成果 | B 的事件和任务契约 |
| E. Mira Novel Studio 接入 | 独立小说项目 + 本仓库接入配置 | 外部静态包、旧作品与生成闭环；主仓库退出小说业务源码 | B 的模型、存储与生命周期契约 |
| F. 应用中心与分发 | 主程序 + Shell | 官方应用目录、安装更新与恢复 | B、C、E 的入口和版本约定 |
| G. 数据迁移与质量 | 主程序 + 两应用 | 旧数据保全、回归矩阵与发布证据 | 随 A–F 并行，发布前收口 |

建议的**最短验证路径**：先审计现有 Electron/Harness/小说依赖并调研开源 Agent UI，明确 A/B/C 的边界和 D 的选型；用现有 Harness 和小说业务验证 SDK，再由独立 Novel Studio 项目提供本地静态包并完成 E 的接入与旧作品验收；最后 F 接远程 Release 和安装事务，由 G 贯穿并完成总验收。旧结构下的原型测试只是技术摸底，不能充当新架构验收；安装器不能替代外部子应用闭环。

阶段 0 的实际源码审计与候选初筛见 [MIRA_PHASE0_AUDIT.md](./MIRA_PHASE0_AUDIT.md)。它记录第一批改动建议，不把本 PRD 的 P0–P3 自动标记为通过。

## 3. 模块关口

### A. Electron 平台服务

**改动边界**：拆解 `electron/main.ts`、`electron/preload.ts` 中集中职责，按启动装配、IPC、业务服务、存储、外部适配、安全边界逐块迁移；不是一次性重排目录。Harness 运行时、模型凭据与文件访问由桌面侧负责；现有小说存储在迁出过渡期保持可用，后续是否继续作为平台服务由数据归属评审决定，不让独立项目直接依赖主进程内部源码。

| 关口 | 交付与验收 |
| --- | --- |
| P0 | 列出窗口生命周期、IPC 调用方、模型/供应商、Harness 任务、小说 API 与数据路径；标记哪些是宿主私有接口。选定首批切分目标与无行为变更的回归用例。 |
| P1 | 入口只装配首批已切分的服务；IPC 做应用身份、参数和权限检查，业务行为仍由服务执行。现有 Harness 会话与小说读写继续可用；相关单测及类型检查通过。 |
| P2 | SDK 所需的模型、任务、成果、存储服务由平台适配提供；密钥留在主进程，前端不可直接得到全量 preload。切换和卸载页面不终止宿主任务。 |
| P3 | 打包后在 macOS / Windows 分别验证窗口、原生菜单、文件访问、长任务和模型调用；错误可定位，旧 IPC 调用方未误断。 |

### B. Platform SDK 与长任务

**改动边界**：从现有 IPC 提炼 Context、Models、Harness、Tasks、Artifacts、Storage、Navigation 的最小接口；独立子应用按身份调用允许的能力，不直接依赖本仓库的 Pinia、Electron 内部模块或其他应用的数据表。Wujie 只承载界面与生命周期，不承担安装器或任务执行器。本仓库应用配置只声明受控身份、入口、版本、能力与安装来源，不替代外部项目的业务实现。

| 关口 | 交付与验收 |
| --- | --- |
| P0 | 定义首版接口字段、调用方身份、必要能力、错误码、订阅清理和 Shell/API/应用三类版本兼容规则；模型连接、能力描述、应用默认绑定分离，但数据结构需评审。 |
| P1 | 一条 Harness 真任务经适配层提交并取得 `taskId`；页面关闭后可查询状态。任务记录所属应用、业务对象和成果引用；创建支持幂等标识，取消区分请求与终态。 |
| P2 | 小说经 SDK 调用真实文本模型与本应用存储；事件有任务 ID 和递增序号，重新挂载时快照加游标恢复或去重。审批在跨应用切换后仍可找到，能力不可用返回明确错误。 |
| P3 | 旧应用/新宿主、缺少能力、订阅重放、重启后状态、取消与重复点击均有测试；破坏性 API 升主版本，不兼容安装在激活前被阻止。 |

### C. Vue Shell 与统一设置

**改动边界**：Shell 只负责外层窗口、全局搜索、应用选择、任务入口、昼夜主题和统一设置；中间纯白应用区由当前应用设计。Harness 会话、项目、审批及成果导航由 React 应用负责，Shell 不规定应用是否使用侧栏。不以旧 Harness 三栏作为内层布局约束。新设置页按基础、平台能力、模型与应用绑定、应用中心、应用专属、关于分组；项目/作品参数留在应用工作区。

| 关口 | 交付与验收 |
| --- | --- |
| P0 | 出两层布局设计稿，标出外层窗口、全局搜索、应用显示区、应用切换和设置返回；确认应用内导航完全归各应用，再动业务页面。 |
| P1 | 默认进入内置 Harness；白天/黑夜可切换。清理自由微应用录入、菜单树管理、壳级路由多页签及布局/主题色/加载动效/图标库的用户配置，包括专用路由、状态和无用分支；保留系统菜单、业务切换及必要加载反馈。 |
| P2 | 同一设置入口管理实际可用的供应商连接、模型能力和两应用默认模型；切换到已安装小说，主题和导航一致，任务入口能回到来源应用，不出现双侧栏/双顶栏。开发入口仅在本机配置可见。 |
| P3 | 旧设置路由回到有效入口，旧偏好不复活退出功能；历史会话、作品、模型配置未误删；两端桌面验证标题栏拖动、焦点、弹层、输入法及真实鼠标点击。 |

## 4. 批次放行与第一阶段完成标准

1. **首批评审**：先完成现有依赖审计和开源 Agent UI 候选对比，确定 A/B/C 的职责、UI 路线、首个真实任务用例、小说迁出清单和数据回退方案。此时不同时启动 React 全量迁移、数据库重写、仓库拆分与安装器上线。
2. **平台与本地双应用闭环**：A、B、C、D、E 至少通过各自 P2，G 完成相应旧数据检查；本仓库 Harness 与独立 Novel Studio 包可在同一 Electron 中完成真实任务，切换不丢任务和草稿。
3. **分发闭环**：F 通过 P0–P3，G 完成安装失败与数据兼容检查；安装更新不破坏旧版本或用户数据。
4. **最终发布**：A–G 均通过 P3；首次离线启动、真实模型、两应用切换、历史恢复、下载损坏/不兼容/回退、主题和生产入口按原方案第 13.2 节逐项验收。
