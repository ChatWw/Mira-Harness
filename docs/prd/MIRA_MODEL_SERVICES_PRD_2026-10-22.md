# Mira 模型服务改造 PRD

版本：v0.1 · 评审稿  
日期：2026-10-22  
交付范围：产品需求与交互原型；尚未修改业务实现。  
平台：Electron 桌面端，macOS / Windows；本次不涉及移动端。

## 1. 产品判断

模型服务的核心任务是「接入服务 → 添加模型 → 在任务中使用」。普通用户应该只需知道服务地址、密钥与想使用的模型，不应该先研究上下文长度、推理参数和多模态协议。

本版采用以下设计：

- 保留 Mira 现有设置框架与视觉语言，借鉴 Cherry Studio 的服务商管理、模型发现及检测流程。
- 内置一个离线可用的**模型能力目录**，为准确匹配的模型补齐参数；不将其做成面向用户的知识库管理功能。
- 区分「模型支持」「服务商开放」「Mira 已接入」三个层次。模型能看图，不代表某网关、协议或 Mira 的附件链路能发送图片。
- 已知参数自动带入，未知参数明确显示「待确认」，高级用户可覆盖并恢复。没有依据时不填写看似准确的默认值。
- 移除模型配置中的单价、币种和费用估算，以及遗留费用展示；保留 Token 使用事实、上下文占用与运行诊断。

**本稿的范围假设：** 用户提出的计费移除指费用估算，不扩大为删除所有 Token 统计。现有设置里的「用量统计」已是 Token / 活动统计，并非账单页；原型不另造一个统计页面。该边界可在评审中调整。

## 3. 目标、非目标与成功标准

### 目标

1. 接入常见服务时不需要填写模型能力；已知模型一键添加。
2. 自定义模型允许添加，不强迫用户猜参数，也不伪装已知能力。
3. 用户能看懂「已启用」「配置未完成」「未检测」「检测通过 / 失败」各自的含义。
4. 选中的协议、输出限制与有效能力真实影响请求和附件入口。
5. 设置页没有单价、币种、估算费用或「已计价」等元素。

### 非目标

- 不复制 Cherry Studio 的完整设置系统或商业服务推荐。
- 不新增图像生成、音频、Embedding、Rerank 管理入口；没有对应消费链路的能力不展示为可用。
- 不做支付、余额、充值、账单同步或成本估算。
- 不承诺一次小额检测能够验证所有能力、上下文上限或长期可用性。
- 不在本轮文档与原型阶段迁移真实模型配置、读取真实密钥或发起付费调用。

### 产品验收基线

普通接入路径只要求服务连接信息和模型选择。高级参数默认收起。模型没有进入目录，也不会出现假的上下文长度或「不支持」结论。检测通过只报告完成的测试项。升级后原有可用模型、角色绑定、会话与地址继续可用。

## 4. 信息架构与页面

```text
设置 / 模型服务
├─ 服务商列表：搜索、已添加的服务实例、添加服务商
└─ 选中服务商
   ├─ 标题：名称、协议摘要、启用开关、更多操作
   ├─ 已添加模型：搜索、发现模型、手动添加
   │  └─ 模型详情：能力、上下文、来源、手动覆盖、检测、移除
   └─ 连接设置：密钥、协议、API 地址、最终地址预览、保存
```

### 视觉与布局

- 沿用现有设置的 13px 正文、12px 辅助说明、15px 分区标题与 22px 页面标题，避免超大表单和重字重。
- 服务列表约 200px，其余空间给连接配置和模型列表；用户不需要在长卡片和大弹窗间反复切换。
- 已添加模型采用紧凑列表：名称 / 实际 ID、有效能力、上下文、检测状态、操作。
- 模型详情、模型发现采用右侧抽屉，连接信息与列表保留在背景，降低上下文丢失。
- 普通添加只显示模型 ID 与名称，能力来自目录；复杂字段放在「调整参数」中。
- 保持 Mira 现有 6 / 8 / 12px 圆角层级、克制的中性色、统一控件高度与悬浮区域。
- Tooltip / Popover / 下拉选项不显示小箭头。沿现有浮层内层动画，定位容器不参与 transform 动画；Tooltip 150ms 进入 / 100ms 退出，抽屉 180ms，支持减少动态效果。
- 支持键盘操作、可见焦点、Esc 关闭、关闭后焦点返回；抽屉限制焦点在自身范围。

## 5. 服务商接入

### 新增

点击「添加服务商」，选择预设或自定义。基础字段：名称、协议、API 地址、认证方式、密钥。预设带入可编辑的连接默认值，预设不等于已经开通的账户。

- 同一家服务商可添加多个实例，实例 ID 与预设 ID 分开；同名实例给出辨识提示，不禁止合法的多账号。
- 首期交付 OpenAI Chat、OpenAI Responses、Anthropic Messages 三类协议的完整链路；Gemini 为后续范围，不提供空入口。
- 本地服务可明确选择「无需密钥」，不根据空密钥猜认证方式。
- 密钥默认遮罩，可替换或明确删除；空白输入表示不修改已保存密钥。清除密钥必须是独立动作。
- 保存成功后才更新真实配置；切换服务、关闭设置或离开页面时，未保存更改提供保存 / 放弃 / 取消。
- 多密钥顺序轮询与多协议独立地址放第二期，不在首期塞入一个复杂表单。

### 地址规则

基础地址和完整请求地址采用明确模式，并显示最终 URL。基础模式按协议规则拼接；完整模式不再自动追加路径。模型发现地址与对话地址分别解析，不能把完整对话地址直接追加 `/models`。

旧配置保留旧地址解释模式，不全局替换或自动重写已保存地址。Cherry 的 `#` 是其产品约定，首期不要求用户学习该符号。使用完整地址且无法推导发现端点时，允许高级配置发现地址，或提示改用手动添加。

### 启用与删除

- 启用只代表参与模型选择，不代表检测通过。连接信息缺失时禁止启用并指出缺失项。
- 未检测但配置完整的模型可用于手动尝试，选择器显示未检测状态；不以未检测为由强迫付费测试。
- 移除 / 停用模型或服务前，列出受影响的默认角色、智能体、工作流绑定，要求先替换或明确解除，不能静默切换到另一模型。
- 不终止运行中的请求；当前运行保持启动时配置快照，后续运行使用新配置。历史记录保留模型身份。

## 6. 模型发现、添加与编辑

### 发现模型

1. 点击「发现模型」使用当前已保存连接获取列表；有未保存更改时先处理草稿。
2. 展示接口返回的真实 ID；支持按 ID / 名称搜索、逐项选择与批量添加。
3. 每一项都做能力目录精确匹配；未知项显示「参数待确认」，不隐藏。
4. 已添加模型显示「已添加」且不能重复添加；刷新不会自动移除远端暂时未返回的本地模型。
5. 空列表、鉴权失败、超时与接口不支持分开提示；始终保留手动添加入口。

### 手动添加

- 必填模型 ID；名称可选，默认沿用 ID。显示名称不参与请求。
- 输入完整 ID 后匹配当前服务 / 协议的目录条目，展示能力摘要与来源。
- 别名不做字符串相似度猜测。自建网关的别名可由用户主动关联目录条目，仅引用参数，不修改请求 ID。
- 未知模型允许保存；显示「已添加 · 参数待确认」。手动映射明确标注为用户关联，不标成目录自动识别。
- 不再让用户逐个回答「是否多模态」再允许添加。

### 详情与高级覆盖

默认展示图片输入、工具调用、推理、PDF / 视频输入（仅在实际链路支持时）、上下文容量、最大输出，以及数据来源。能力为「支持 / 不支持 / 待确认」，不能用一个多模态开关代表所有模态。

点击「调整参数」才进入覆盖模式。字段默认继承识别结果，可单独设置或恢复；覆盖值旁标「手动设置」。恢复自动只清除相应覆盖，不删除模型。若自动值未知，恢复后仍是未知。

模型支持推理是能力元数据；是否开启推理、推理强度是调用偏好，不能共用一个开关。模型支持工具不代表所有协议中的工具请求已经兼容。

## 7. 内置模型能力目录

### 为什么要内置

`/models` 通常只能返回 ID，不能可靠提供图片支持、上下文或工具兼容性。普通连通性检测同样不能补全这些信息。内置目录是必要的，但不能把未经核验的表格包装成权威答案。

### 数据来源与维护

1. 优先使用供应商官方模型文档中的能力与限制，并保留 URL、核验日期、模型版本 / 端点适用范围。
2. 已安装 pi-ai 的模型目录、models.dev 等公开目录可作为候选数据；上线前核对字段语义、授权与覆盖情况，不直接把第三方结果作为官方事实。
3. 现有 `modelKnowledge.ts` 作为迁移输入。缺少证据的旧条目标「历史配置 / 待核验」，不沿用成已验证自动识别结果。
4. 首批覆盖现有六家预设中有明确官方依据的常用模型，并随协议扩展纳入对应模型。验收以已核验覆盖清单为准，不用凑数量。
5. 首期以随应用发布的版本化快照更新，离线可用，不增加远程执行或联网刷新依赖。更新不得覆盖用户手动参数。

### 匹配与优先级

- 匹配键至少包括服务商 / 目录命名空间、协议、精确模型 ID；区域、端点类型存在能力差异时一并限定。
- 日期模型、供应商前缀和大小写语义必须尊重实际 API，禁止无依据地截断、模糊匹配或全局小写归并。
- 只为有明确证据的别名建立映射；未知别名不自动套用名字相近模型的参数。
- 参数优先级：用户覆盖 → 该服务接口明确返回且适用于当前模型的元数据 → 已核验内置目录 → 未知。
- 逐字段保留来源；普通检测只形成独立检测记录，不能由一次成功反向推出容量或全部能力。
- 有效功能取模型 / 用户声明、服务与协议可用性、Mira 适配能力的交集；遇到明确不支持的链路，手动声明也不能解锁空能力。

### 未知参数的运行策略

未知不等于不支持。文本聊天可尝试；图片等输入在能力未确认时不自动开放，入口提供说明和参数确认路径。

Harness 的工具执行要求工具能力明确支持，或完成用户主动触发的工具兼容检测；否则在模型选择时标出「工具能力待确认」，不等到任务执行中才丢工具。

上下文容量未知时不显示占用百分比。宿主使用单独的保守本地发送预算，首期建议 16,384 Token，并扣除输出预留与协议 / 工具开销；预算只约束本地发送，文案明确不代表服务上限，也不能保证任意未知模型都能接受。供应商仍可能拒绝，错误应提供手动设置入口。最大输出不得超过已知上限，未知时只发送经当前适配器验证的默认预算，不能把 8192 当作模型事实。

## 8. 检测与状态

### 独立状态

| 维度 | 状态 | 含义 |
| --- | --- | --- |
| 服务配置 | 未完成 / 已保存 | 必要连接信息是否齐全 |
| 启用 | 已启用 / 已停用 | 是否参与后续模型选择 |
| 模型资料 | 已识别 / 手动设置 / 部分待确认 | 参数的确定性与来源 |
| 最近检测 | 未检测 / 检测中 / 通过 / 失败 / 已过期 | 对某配置快照与模型执行过哪些测试 |

连接地址、协议、密钥或相关模型参数改变后，旧检测记录保留但标为过期。其他模型不共享本模型的成功结果。

### 检测范围

- 基础检测：用户选择模型，发起最小文本请求，验证有效响应；展示「会产生少量模型用量」，不显示估算金额。
- 按需检查：流式输出、工具调用、图片等分别报告，不自动发起昂贵的多模态 / 大上下文测试。
- 工具检测只使用受控回显工具，不执行本机文件、Shell、网络或业务操作。
- 请求路径、认证、协议与参数解析复用生产调用链。提供取消；默认 15 秒超时，最终实现可按适配器调整并在界面显示。
- 区分鉴权失败、模型不存在、协议不兼容、限流、网络错误、超时和无有效内容；支持重试与编辑配置。
- 结果展示协议、模型 ID、检测项目和时间，不展示完整密钥、认证头或未脱敏响应。

## 9. 移除计费的边界

### 删除的产品能力

- 模型编辑中的「用量估算」、币种、输入 / 输出 / 缓存单价。
- 模型列表中的「已计价 / 未计价」。
- 仍可访问的旧前台「用量与成本」中的费用入口、金额、费用导出与相关导航；旧费用路由跳转到现有不含费用的统计页，或在无等价入口时返回模型设置。
- 新配置中不再写入价格；新的运行记录不再由用户单价计算费用。

### 保留的数据与能力

- 供应商实际返回的 Token 用量与明确标注的本地估算；来源缺失时不伪装为实测。
- 上下文预算、压缩触发、缓存相关 Token 及排障所需的原始运行记录。
- 现有设置中的纯 Token / 使用活动统计。
- SDK 若结构上要求 cost 字段，可以保留适配占位，但不得转化为产品金额，也不应把 0 展示为免费。

旧价格与历史估算记录首期兼容读取、不参与新计算、不展示、不批量删除历史文件。后续清理存储另行评估，不将删 UI 扩大成不可逆的数据清除。

## 10. 能力层与配置迁移

以下是实现约束，正式开发时可沿既有类型命名细化，不要求新增大型配置框架。

| 对象 | 主要新增 / 调整字段 | 约束 |
| --- | --- | --- |
| 服务实例 | 独立 ID、预设引用、协议、地址模式、基础 / 完整地址、认证方式、启用 | renderer 只拿密钥是否存在；宿主持有凭据 |
| 模型实例 | 精确请求 ID、显示名称、启用、目录关联、参数覆盖 | 唯一身份由服务实例 ID + 模型 ID 组成 |
| 目录记录 | 匹配范围、能力三态、上下文 / 最大输出、逐字段来源 / 日期、目录版本 | 不包含计费；未发布字段可缺失 |
| 检测记录 | 配置指纹、模型身份、检测项、结果、耗时、时间 | 指纹使用凭据版本标识，不暴露密钥或可离线猜测的密钥摘要 |

迁移要求：

1. 写入前备份并校验配置，采用版本升级与原子写入，失败保留原文件。
2. 保留 provider UUID、legacyIds、角色 / 智能体 / 工作流绑定，不因显示名变化改身份。
3. 老版本无法区分手动值与自动填充值的字段，按历史覆盖保留；后续可由用户恢复自动，不能静默重置。
4. 老地址保留旧解析模式；已有上下文容量继续生效，不能在升级时被未知状态替换。
5. 主 Agent、子 Agent、摘要、记忆、工作流、验证与小说调用方均复核，不让设置和某个消费者各自维护协议解释。
6. 密钥不进入第一方应用桥、原型、分享数据、日志或诊断导出。配置损坏给出恢复路径，不用空配置覆盖。

## 11. 交付分期与验收

### 第一期：可用闭环

服务实例 CRUD、地址预览、单密钥 / 无认证、三种协议、模型发现与批量添加、能力目录与覆盖、真实链路检测、模型选择器联动、费用移除、旧配置迁移。每一种上线协议都必须具备实际请求、流式、取消、错误处理与工具链验收；未完成的协议不发布可选入口。

### 第二期：高级接入

多密钥按顺序轮询、逐密钥测试、同服务多协议独立地址、自定义请求头、批量检测；Gemini 独立完整适配。不把「多密钥」自动等同于失败切换，不默认跨密钥重试已发送请求。

### 验收矩阵

| 场景 | 必须达到的结果 | 验证方式 |
| --- | --- | --- |
| 已知模型 | 自动补齐有依据字段，显示来源与精确 ID | 目录单测 + 桌面交互 |
| 未知 / 别名 / 日期模型 | 不模糊套值，不显示假容量；可手动添加 / 关联 | 匹配反例单测 + 原型 / 桌面 |
| 手动覆盖后更新目录 | 覆盖不丢失；恢复自动仅清除对应覆盖 | 配置测试 |
| 图片支持但 PDF 不明确 | 图片和 PDF 分别受控，不能联动勾选 | 媒体适配与桌面验收 |
| 多实例 / 同 ID 模型 | 无串配置、串检测、串密钥或误合并 | 存储 + 模型选择器测试 |
| 查询失败 / 空列表 / 不支持发现 | 原列表不丢失，手动添加仍可用 | 受控接口 + 桌面交互 |
| 检测成功后修改地址 / 密钥 | 原结果过期，不继续显示有效成功 | 配置快照测试 |
| HTTP 200 但无有效模型响应 | 检测失败，不能只看状态码 | 受控接口回归 |
| 工具与取消 | 按协议验证流式工具往返，取消后无残留执行 | 受控模型端到端 + 真实服务抽验 |
| 删除被绑定模型 | 明确阻止或要求替换，运行中任务保持快照 | 绑定 / 运行测试 |
| 升级老配置 | 地址、密钥、手动参数、绑定与会话保持 | 老配置夹具 + 重启验收 |
| 删除费用 | 设置及可访问旧路由无金额 / 单价；Token 与压缩仍工作 | 定向代码检索 + 桌面回归 |
| 浮层与桌面窗口 | 明暗主题、长 ID、不同桌面窗口宽度、键盘关闭无裁切漂移 | macOS Electron；Windows 单独验收 |

原型中的模型参数、服务状态与检测结果均为交互演示，不构成上表中真实模型、协议和迁移验收的完成证据。

## 12. 原型评审路径与参考

建议按顺序体验：

1. 查看已识别模型详情，展开来源和「调整参数」。
2. 发现模型，搜索、勾选并批量添加；搜索不存在的模型体验空态。
3. 手动添加未知模型，观察参数待确认；尝试手动设置与恢复自动。
4. 切换服务商、进入连接设置、切换协议及地址模式，查看最终 URL。
5. 模拟检测通过、超时和鉴权失败，观察状态变化；原型不发网络请求。
6. 新增自定义服务，保存连接，添加模型；停用后观察模型列表的使用提示。
