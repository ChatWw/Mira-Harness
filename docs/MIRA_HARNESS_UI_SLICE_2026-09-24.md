# Mira-Harness 任务状态 UI 切片（2026-09-24）

## 目标

让消息区、错误卡和右侧工作面板对同一次 Harness 运行使用同一组用户可理解的状态，避免任务失败、停止或整理回复时被显示为“已完成”。本批只调整状态呈现，不改变运行器、IPC、会话数据或权限协议。

## 状态契约

| 状态 | 工作面板主文案 | 视觉提示 | 可见信息 |
| --- | --- | --- | --- |
| `running` | 正在执行任务 | 主色 + 加载图标 | 当前活动、工具和子任务 |
| `rendering` | 正在整理回复 | 主色 + 加载图标 | 已完成工具、等待回复整理 |
| `failed` | 任务失败 | 错误色 + 关闭图标 | 已完成活动、错误摘要；重试仍由消息区提供 |
| `stopped` | 任务已停止 | 次要色 + 暂停图标 | 已生成内容保留，活动记录可展开 |
| `completed` | 最近任务已完成 | 成功色 + 完成图标 | 文件变更和执行记录 |
| `idle` | 尚无任务记录 | 次要色 + 时钟图标 | 空态说明 |

状态来源按优先级处理：当前运行的 `running/rendering`，最近完成消息的 `failed/stopped/completed`，最后才使用面板自身的 `idle`。这样停止和失败不会被主进程结束事件发出的 `idle` 覆盖。

## 交互边界

- 工作面板继续由用户主动打开，不在每次运行时强制弹出。
- 工具详情保持折叠/展开；失败详情不自动展开，避免长日志打断对话。
- 重试、继续回复、审批和停止按钮继续由消息区/输入区负责，面板只提供状态和结果定位。
- 本批不新增“排队消息”、运行中草稿和文件 diff 编辑能力。

## 验收

- 组件测试覆盖六种面板状态的文案、图标和错误摘要。
- 现有全量测试、类型检查和构建继续通过。
- Electron 视觉、真实鼠标、打包版和真实模型仍按交接文档分别记录，不由静态测试代替。
